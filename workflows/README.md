# تجهيز بيانات المشاركين

Participant Data Preparation

| البند | القيمة |
|---|---|
| الحالة | لم يبدأ التنفيذ |
| المسؤول | يُحدد لاحقًا |
| المراجع | يُحدد لاحقًا |
| ملف الأتمتة | [workflow.json](workflow.json) |

## الهدف

جمع البيانات الإضافية من المشاركين المؤكدين ومتابعة استكمالها.

## المدخلات والإعدادات المطلوبة

- قائمة المشاركين الذين أكدوا الحضور.
- نموذج البيانات الإضافية والحقول المطلوبة.
- مواعيد التذكير والمهلة النهائية للاستكمال.

## السلوك المطلوب عند اكتمال التطوير

1. إرسال نموذج استكمال البيانات للمشاركين المؤكدين.
2. ربط الرد بالمشارك الصحيح والتحقق من اكتمال الحقول المطلوبة.
3. إرسال التذكيرات لمن لم يكمل بياناته.
4. تجهيز قائمة نهائية بالمشاركين المؤكدين والمكتملة بياناتهم.

## المخرجات

قائمة المشاركين الجاهزة للاستخدام مع حالة اكتمال بيانات كل مشارك.

## البدء والتسليم

1. استورد `workflow.json` إلى نسخة n8n المحلية. الملف الحالي قالب فارغ وغير مفعّل لبدء العمل؛ لا ينفذ الوظائف المذكورة أعلاه.
2. ابنِ الخطوات واربط الخدمات باستخدام بيانات تجريبية.
3. وثّق أسماء الخدمات والإعدادات المطلوبة هنا، دون نسخ القيم السرية.
4. اختبر الحالات أدناه، ثم صدّر الأتمتة واستبدل القالب بالنسخة المطورة.
5. ارفع التعديلات في فرع خاص بالنظام وافتح Pull Request للمراجعة.

إذا احتاج النظام أكثر من Workflow، يُحفظ كل واحد في ملف JSON مستقل باسم واضح داخل هذا المجلد، ويُشرح ترتيب تشغيلها هنا.

## حالات التحقق قبل التسليم

- اختبار ربط الرد بالمشارك الصحيح.
- اختبار الرد المكتمل والرد الناقص.
- التأكد من توقف التذكيرات عند اكتمال البيانات.

## الربط مع الأنظمة الأخرى

استخدم `event_id` لتمييز الفعالية و`participant_id` لتمييز المشارك. اتفق مع مسؤولي الأنظمة الأخرى على أسماء الحقول والحالات قبل الربط.
